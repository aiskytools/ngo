# 9. Internationalization (Multi-language)

The site is multilingual via **next-intl** with URL-based locale routing.

| Locale | Code | URL prefix |
|---|---|---|
| English (default) | `en` | `/en/...` |
| Hindi (हिन्दी) | `hi` | `/hi/...` |
| Marathi (मराठी) | `mr` | `/mr/...` |

Visiting `/` redirects to `/en`. A **language switcher** (globe icon) sits in the navbar on every page
and preserves the current page when switching.

---

## How it's wired

```
i18n/
  routing.js      locales + defaultLocale (en) + localePrefix: "always"
  navigation.js   locale-aware Link / usePathname / useRouter (createNavigation)
  request.js      loads messages/<locale>.json per request
middleware.js     next-intl middleware (redirects + locale detection)
messages/
  en.json hi.json mr.json   translation catalogs (namespaced)
app/[locale]/     all public pages + admin live under the locale segment
  layout.js       <html lang>, NextIntlClientProvider, localized <metadata>
next.config.mjs   wrapped with createNextIntlPlugin('./i18n/request.js')
```

- **Routing**: every route is under `app/[locale]/`. API routes (`app/api`), `sitemap.js`, and
  `robots.js` stay at the app root and are **not** localized (the middleware matcher excludes `/api`,
  Next internals, and any path with a file extension).
- **Links**: components use `Link` / `usePathname` / `useRouter` from `@/i18n/navigation` so navigation
  keeps the active locale. Don't use `next/link` for internal links.
- **Strings**: components read copy via `useTranslations("namespace")` (client or server) or
  `getTranslations` (server). Keys live in `messages/<locale>.json`.
- **Admin** is reachable at `/<locale>/admin` (e.g. `/en/admin`).

## SEO

- `<html lang>` is set per locale.
- Page `<title>`/description are localized (layout `generateMetadata` + the `meta` namespace).
- **hreflang + canonical** are delivered per-URL via the **sitemap** (`app/sitemap.js`), which lists
  every page under all three locales with `alternates.languages`. (Head-level alternates are
  intentionally omitted because a shared layout can't know the child path.)
- Set `NEXT_PUBLIC_SITE_URL` at build time so these URLs are correct.

## Adding / editing translations

1. Add the key to **`messages/en.json`** (source of truth) inside the right namespace.
2. Add the same key to `messages/hi.json` and `messages/mr.json`.
3. In the component, read it: `const t = useTranslations("namespace"); …{t("key")}`.

To translate a page body that's currently English, replace its hardcoded strings with `t(...)` calls
and add the keys to all three catalogs. Keep keys identical across locales — a missing key throws in
development.

## Adding a new language

1. Add the locale code to `i18n/routing.js` (`locales`).
2. Create `messages/<code>.json` (copy `en.json` and translate).
3. Add the display name under the `language` namespace in every catalog.

That's it — routing, the switcher, and the sitemap pick it up automatically.
